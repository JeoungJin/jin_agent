# 교안(Day1~Day3) 순서대로 구현·검증한 결과 리포트

방법: 교안의 Vibe Coding 프롬프트와 확인용 curl 을 **문서 순서 그대로** 구현·실행했고, 실제 서버(FastAPI 9000 · Spring 8000 · React 5173)를 띄워 확인했습니다.
결론: **React · Spring · FastAPI 모두 문서 순서대로 구현되고 3-tier 가 왕복합니다.** 아래 항목만 교안 수정이 필요합니다.

## 검증 결과 요약

| 영역 | 자동 테스트 | 실서버 확인 |
|---|---|---|
| Day1 터미널 Assistant | pytest 20개 | 10개 질문 분류·Tool·빈 입력 |
| FastAPI (Day2~3) | pytest 53개 (yfinance 모킹) | /docs, /chat, /route(SSE), /portfolio |
| Spring | JUnit 31개 (MockWebServer·StepVerifier·MockMvc) | JWT 쿠키, fallback, 계좌 403/404, SSE 중계, 포트폴리오 프록시 |
| React | vitest 5개(parseSse) + tsc + build | Playwright(Chromium): 로그인 → 스트리밍 채팅(글자 단위 증가) → 대시보드 → 로그아웃 |

## 꼭 고쳐야 할 곳 (그대로 따라 하면 막히거나 틀린 결과)

| # | 위치 | 문제 | 수정 제안 |
|---|---|---|---|
| 1 | Day2 4-1 확인 curl | Spring 이 FastAPI `/api/v1/chat` 을 호출하면 "내 잔액", "삼성전자 주가"도 **LLM 이 답함**(Tool 미실행). `/chat` 은 LLM 전용 | Spring 호출 대상을 `/api/v1/route` 로 (4-4 계좌조회 전에 이미 필요) |
| 2 | Day2 4-1 ~ 4-2 (Mono 반환) | Mono 를 반환하는 컨트롤러 + Spring Security 조합에서 **유효한 쿠키인데도 401** (ASYNC 재디스패치 재인가). 현재 교안은 Day3 Step2 [6] 에서야 `ASYNC·ERROR permitAll` 언급 | Day2 4-2 JWT 프롬프트에 "SecurityConfig: `dispatcherTypeMatchers(ASYNC, ERROR).permitAll()`" 추가, Day3 의 [6]은 "이미 적용됨"으로 |
| 3 | Day3 Step2 확인 curl | 경로가 `/api/ai/route-stream` 으로 되어 있으면 쿠키 없을 때 401, 있으면 404. 구현 경로는 `/api/ai/route` (`produces=event-stream`) | curl 경로를 `/api/ai/route` 로 통일 |
| 4 | Day3 3-3 [4] "route/chat 공통" 과 확인 curl | `/api/v1/chat` 은 LLM 전용이라 "삼성전자 주가 알려줘"에 Tool 문장이 안 나옴 (가짜 LLM/LLM 답변) | 확인은 `/api/v1/route` 로. [4] 문구에서 "/chat 공통" 삭제 |
| 5 | Day3 4-1 ↔ 4-2 순서 | Recharts(4-1)를 먼저 만들면 `/api/ai/portfolio` 가 **404** → 대시보드가 에러 상태만 보임. 수강생이 코드 오류로 오해 가능 | 4-2 Step1(Spring 프록시)을 4-1 앞으로, 또는 4-1 시작 전에 "404면 에러 UI가 정상" 안내 |

## 권장 수정 (막히진 않지만 혼란 예상)

| # | 위치 | 내용 |
|---|---|---|
| 6 | Day2 4-2 / 4-4 | 서버 간 호출(FastAPI→Spring 내부 API)은 쿠키가 없으므로 JWT 필터가 **쿠키 → Bearer 순**으로 토큰을 읽어야 함. 프롬프트에 "Authorization: Bearer 도 허용" 한 줄 필요 |
| 7 | Day2 4-3 | Mono 용 `AiRouteResponse` fallback 상수는 Day3 Flux 전환 후 쓰이지 않음 → Day3 에서 "fallback 은 error 이벤트로 대체"를 명시 (코드 삭제 지시) |
| 8 | Day3 Step3 | 컨트롤러는 4xx 도 `produces=event-stream` 이라 JSON 에러 본문 Content-Type 을 JSON 으로 강제해야 React 의 `res.json()` 이 동작. Step2 [5]에 한 줄 추가 |
| 9 | Day3 4-1 | `npm i recharts` 가 프롬프트에 없음(Vibe 가 설치하지만 명시 권장). Recharts 3.x 에서는 `onClick` 인자의 데이터가 `d.payload` 안에 있음(타입 오류 사례) |
| 10 | Day3 3-3 | **yfinance 실거래 시세는 이 검증 환경(외부망 차단)에서 확인하지 못했습니다.** 모킹 테스트와 실패 경로(5초 후 503/안내문)만 검증. 수업 전 강사 PC 에서 `GET /api/v1/portfolio` 한 번 호출 확인 필요 (`fast_info['last_price'/'previous_close']` 사용, Yahoo 차단 시 캐시/안내문 동작) |
| 11 | Day3 3-3 | 종목 추출이 "첫 번째 일치"라 "삼성전자와 삼성SDI 비교" 는 삼성전자만 답함 — 수강생 질문 대비 한계로 안내 |
| 12 | Day3 Step2 주의 박스 | 타임아웃 3초 → 10초 권고는 이미 문서에 있으나 Day2 4-3 의 3초 설정이 그대로 남아 있음. Day2 에서 처음부터 `ai.fastapi.timeout: 10s` 로 두면 Day3 에서 바꿀 일이 없음 |

## 문서 순서의 자연스러움 (판단)
- Day1 → Day2(FastAPI 서버화 → Spring → JWT → Fallback → 계좌) → Day3(SSE → Spring 중계 → React → yfinance → 대시보드 → 연결) 흐름은 **자연스럽게 이어집니다.**
- 막히는 지점은 위 #1, #2, #5 세 곳(앞 단계 설정이 뒤 단계에서야 나오거나 순서가 역전).
- "Vibe Coding 만으로 되는가": 프롬프트의 [규칙] 항목(이벤트 이름, user_id 미전송, 4xx 전파, ASYNC 설정)이 구체적이라 구현 결과가 일관됩니다. 단 #2 처럼 **환경 함정**은 프롬프트에 없으면 AI 도 놓칩니다.
