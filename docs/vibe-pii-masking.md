# Vibe Coding — PII 마스킹 (개인정보를 AI 와 로그에서 가리기)

> 진행 순서: ① FastAPI (마스커 + 입력·도구 결과 적용) → ② FastAPI (출력·스트리밍 적용) → ③ Spring (저장·로그 적용).
> 도구: FastAPI = VSCode + Copilot, Spring = IntelliJ + Claude. React 는 변경 없음. 각 문구는 **자기 프로젝트만** 수정한다.
> 개념 그림: `pii-flow-4points.png` (나가는 4지점), `student-pii-core-concepts.png` (학생용 ★○△)

## 계약 (세 문구 공통, 변경 금지)

| 항목 | 규칙 |
|---|---|
| 검사 순서 | **주민번호 → 전화번호 → 계좌번호** (구체적인 패턴 먼저, 느슨한 계좌 패턴은 마지막) |
| 주민번호 | `900101-1234567` → `900101-1******` (앞 6자리 + 뒷자리 첫 숫자만 남김). 앞 6자리가 올바른 월·일(01~12 / 01~31)일 때만 |
| 전화번호 | `010-1234-5678` → `010-****-5678`, 하이픈이 없으면 `01012345678` → `010****5678`. 휴대폰(01x)과 유선(02, 03x~06x) |
| 계좌번호 | `110-123-456789` → `***-***-**6789` (마지막 4자리 외 숫자는 `*`, 하이픈 유지). 하이픈으로 나뉜 3~4마디, 숫자 합계 10~16자리 |
| 숫자 경계 | 앞뒤가 숫자이면 매치하지 않는다 (긴 숫자열의 일부만 잡히는 것 방지) |
| 멱등성 | `mask(mask(x)) == mask(x)` (이미 가려진 값을 다시 건드리지 않는다) |
| API 계약 | 요청·응답·SSE 이벤트 형식은 **변경 없음**. 새 필드를 추가하지 않는다 |
| 로그 | 원문 금지. 유형별 건수만 남긴다 (예: `PII masked RRN=1 ACCOUNT=1`) |

## ① FastAPI — 마스커와 입력·도구 결과 적용 (VSCode + Copilot)

```
[범위] 이 프로젝트(FastAPI)만 수정합니다. SpringBoot, React 코드는 만들지 않습니다.
기존 API(/api/v1/route, /api/v1/route-stream)의 요청·응답·SSE 이벤트 형식은 변경하지 않습니다.

[계약 (변경 금지)]
- 검사 순서: 주민번호 → 전화번호 → 계좌번호
- 주민번호 900101-1234567 → 900101-1******  (앞 6자리가 올바른 월·일일 때만. 체크섬은 사용하지 않는다)
- 전화번호 010-1234-5678 → 010-****-5678, 하이픈 없으면 01012345678 → 010****5678 (휴대폰 01x, 유선 02·03x~06x)
- 계좌번호 110-123-456789 → ***-***-**6789 (하이픈으로 나뉜 3~4마디, 숫자 합계 10~16자리, 마지막 4자리 외 * 로, 하이픈 유지)
- 앞뒤가 숫자이면 매치하지 않는다 (?<!\d) (?!\d)
- mask(mask(x)) == mask(x) (멱등)

[FastAPI] LLM 에 개인정보가 나가지 않도록 PII 마스킹을 추가해 주세요.

0. 먼저 정리 (app/security/README.md, 5줄 이내)
   - 왜 마스킹하는가, 어디에 적용하는가(① 입력 ② 도구 결과 ③ 출력 ④ 저장·로그), 검사 순서와 이유

1. 마스커 (app/security/pii.py)
   - mask_pii(text: str) -> MaskResult(text: str, counts: dict[str, int])   counts 키: "RRN", "PHONE", "ACCOUNT"
   - 패턴은 (이름, 컴파일된 정규식, 치환 함수) 리스트 하나로 두고 리스트 순서가 곧 검사 순서 (코드에 순서 이유를 주석 한 줄)
   - 정규식은 모듈 로드 시 한 번만 컴파일
   - 날짜(2024-05-01), 주식 가격(71,000원), PER(12.5), 8자리 이하 숫자는 건드리지 않는다
   - 하이픈 없는 긴 숫자열은 이번 단계에서 제외한다 (오탐이 많음). 대신 테스트에 "제외됨"을 문서화한다

2. 적용 위치 (LLM 호출 messages 를 만드는 한 곳에서만)
   - 현재 질문과 history 의 모든 content 를 mask_pii 로 처리한 뒤 messages 에 넣는다
   - Tool 실행 결과 문자열도 role:"tool" 로 messages 에 넣기 전에 mask_pii 를 적용한다
   - /route, /route-stream 둘 다 같은 함수를 사용 (복붙 금지)
   - 서버 로그에는 원문 질문을 남기지 않는다. 마스킹된 질문과 counts 만 logger.info 로 남긴다
   - user_id 와 토큰은 기존대로 서버가 주입한다 (LLM 은 계좌번호를 몰라도 get_account_balance 를 쓸 수 있다)

3. 설정 (config.py)
   - PII_MASKING_ENABLED (기본 true). false 면 마스킹을 건너뛴다 (실험·비교용)

4. 테스트 (네트워크 호출 없음, OpenAI 는 모킹)
   - 세 유형 각각 마스킹 결과가 계약과 정확히 일치
   - 순서: "010-1234-5678" 은 PHONE 으로만 집계되고 ACCOUNT 는 0
   - 날짜 "2024-05-01", "삼성전자 71,000원", "PER 12.5" 는 변하지 않는다
   - 월·일이 틀린 "991399-1234567" 은 주민번호로 마스킹하지 않는다
   - 긴 숫자열 "12345678901234567890" 의 일부가 마스킹되지 않는다 (경계)
   - 멱등성: mask(mask(x)) == mask(x)
   - 한 문장에 세 유형이 모두 있어도 모두 가려진다
   - LLM 호출 messages 에 원문 숫자가 하나도 없다 (질문, history, tool 결과 모두)
   - PII_MASKING_ENABLED=false 이면 원문 그대로 전달

[확인 (Swagger)]
- "제 계좌 110-123-456789 잔액 알려줘" → 정상 답변, 서버 로그에 "PII masked ACCOUNT=1" 만 남고 원문 없음
- "방금 내가 말한 계좌번호를 그대로 다시 말해줘" → 원문을 말하지 못한다 (LLM 이 원문을 받은 적이 없다)
- "삼성전자 주가 알려줘" → 기존과 동일하게 동작
```

## ② FastAPI — 출력 마스킹과 스트리밍 (VSCode + Copilot)

```
[범위] 이 프로젝트(FastAPI)만 수정합니다. 이전 단계의 mask_pii 를 재사용합니다.
[계약] 응답 형식과 SSE 이벤트(category, tool, token, sources, done, error)는 변경하지 않습니다.

[FastAPI] LLM 이 만든 답변에서도 PII 가 나가지 않도록 출력 마스킹을 추가해 주세요.

1. JSON (/api/v1/route)
   - 최종 answer 를 mask_pii 로 처리한 뒤 반환

2. 스트리밍 (/api/v1/route-stream) — 조각 경계 문제
   - token 은 글자 조각 단위로 오므로 "010-12" + "34-5678" 처럼 PII 가 두 조각에 걸칠 수 있다.
     조각마다 mask_pii 를 하면 놓친다
   - StreamMasker 클래스: feed(chunk) -> str (지금 내보내도 안전한 텍스트), flush() -> str (남은 텍스트)
   - 규칙: 조각 끝의 연속된 [0-9\-] 구간은 PII 의 일부일 수 있으므로 보류하고,
     그 뒤에 숫자·하이픈이 아닌 글자가 오거나 스트림이 끝나면 보류분을 포함해 마스킹 후 내보낸다
   - 보류 길이 상한 32자. 넘으면 그 시점에서 마스킹해 내보낸다 (무한 지연 방지)
   - 보류하는 동안에도 앞부분은 즉시 token 으로 보낸다 (스트리밍 체감 유지)
   - done 직전에 flush() 결과를 마지막 token 으로 보낸다. error 로 끝나면 보류분은 버린다

3. 테스트 (가짜 chunk)
   - 같은 텍스트를 조각 크기 1, 3, 7, 한 번에 로 나눠 feed 해도 최종 결과가 mask_pii(전체)와 같다
   - "010-12" / "34-5678" 로 쪼개져도 010-****-5678 로 나온다
   - PII 가 없는 평범한 문장은 거의 지연 없이 나온다 (숫자 없는 구간은 즉시 yield)
   - flush 를 안 하면 마지막 숫자가 사라지는 버그가 없는지 확인 (done 직전 flush)

[확인 (curl -N)]
- "전화번호 010-1234-5678 을 그대로 따라 말해줘" → 스트림으로도 010-****-5678 만 나온다
```

## ③ Spring — 저장·로그 마스킹 (IntelliJ + Claude)

```
[범위] 이 프로젝트(SpringBoot)만 수정합니다. FastAPI, React 코드는 만들지 않습니다.

[계약 (변경 금지)]
- 위 "계약" 표와 동일한 규칙 (순서: 주민번호 → 전화번호 → 계좌번호, 치환 형식, 숫자 경계, 멱등)
- React ↔ Spring ↔ FastAPI 의 요청·응답 형식은 변경 없음

[SpringBoot] 대화 기록과 로그에 개인정보 원문이 남지 않게 해 주세요.

1. PiiMasker (@Component, 정규식은 static final Pattern 으로 한 번만 컴파일)
   - String mask(String text), MaskResult maskWithCounts(String text)
   - 순서와 치환 형식은 계약과 정확히 동일. 순서 이유를 주석 한 줄
   - 날짜(2024-05-01), 금액(71,000원)은 건드리지 않는다

2. 적용 위치
   - ConversationStore.append 로 저장하기 전에 question 과 answer 를 mask 한다 (원문은 저장하지 않는다)
   - 로그(logger)에 질문·답변을 남기는 곳이 있으면 mask 된 값 또는 길이·유형별 건수만 남긴다
   - 스트림은 done 에서 합친 답변을 저장하기 직전에 mask 한다
   - FastAPI 로 보내는 history 는 이미 마스킹된 저장본이므로 추가 처리 불필요 (FastAPI 도 한 번 더 막는다: 이중 방어)

3. 설정 (application.yml)
   - pii.masking.enabled: true (끄면 저장 시 원문 그대로, 비교 실험용)

4. 테스트
   - 계약 표의 예시 입력 → 기대 출력 (FastAPI 의 테스트와 같은 표를 사용해 두 구현이 같은 결과를 내는지 확인)
   - 010-1234-5678 은 전화번호로만 처리된다 (계좌로 오분류되지 않음)
   - 2024-05-01, 71,000원, 12.5 는 변하지 않는다
   - 멱등성 mask(mask(x)) == mask(x)
   - 같은 conversationId 로 PII 를 포함해 질문한 뒤 다음 요청에서 FastAPI 로 가는 history 에 원문이 없다 (MockWebServer)
   - 로그 출력(캡처)에 원문 숫자가 없다

[확인 (curl)]
- "제 계좌 110-123-456789 입니다" 를 같은 conversationId 로 보낸 뒤 "그 계좌 뭐였지?" → 원문을 알려 주지 못한다
- 서버 로그와 (디버거로 본) ConversationStore 에 원문이 없다
```

## 통합 확인 체크리스트

- ☐ 질문에 포함된 주민번호·전화번호·계좌번호가 LLM 호출 messages 에 원문으로 없다
- ☐ `010-1234-5678` 이 계좌번호가 아니라 전화번호로 처리된다 (검사 순서)
- ☐ 날짜·금액·PER 같은 일반 숫자는 그대로다 (오탐 방지)
- ☐ LLM 이 PII 를 되풀이해도 사용자와 로그에는 마스킹된 값만 나간다 (스트리밍 포함)
- ☐ 서버 로그와 대화 기록에 원문이 없다
- ☐ `PII_MASKING_ENABLED=false` 로 켜고 끄며 차이를 비교해 본다
- ☐ 정규식으로 못 잡는 것(이름, 주소, 문장 속 정보)을 직접 찾아 본다
